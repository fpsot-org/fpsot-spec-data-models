= Versions and deprecation
include::_fpsot-terms.adoc[]

A model changes over time, while systems keep data written under older versions.
These rules apply the stability rules of the {abbr-fpsot-first} naming specification to a model.

== Version numbers

[[DMO-060]]
*DMO-060.* Each release of a model MUST have a version number under link:https://semver.org/spec/v2.0.0.html[Semantic Versioning 2.0.0].
The model version follows the tag of the release in the {term-repository}, such as `v0.1.0`.
The schema MUST hold that number in its `version` slot, without the `v`.
A release that changes only the text of the specification is a patch release, such as `v0.1.1`.
The schema then takes the new number, although none of its elements changes.
The number tells a system whether a new release can break the data it holds.

== Compatible changes

[[DMO-061]]
*DMO-061.* Within one major version, a release MUST NOT remove or rename a class, a slot or an enumeration value.
It MUST NOT change the type or meaning of a slot.
It MUST NOT make an optional slot required, or narrow a pattern.
A minor release MAY add a class, an optional slot or an enumeration value, under NAM-081.
A removed name MUST NOT come back later with another meaning, under NAM-082.
Every record that was valid under an earlier release of the same major version then stays valid.

Before version 1.0.0, link:https://semver.org/spec/v2.0.0.html[Semantic Versioning] allows any change, but {abbr-fpsot} models still follow this rule from 0.1.0.

== Deprecation

[[DMO-062]]
*DMO-062.* To retire an element, a release MUST mark it with the `deprecated` slot of link:https://linkml.io/linkml/schemas/metadata.html[LinkML element metadata].
An element is a class, a slot or an enumeration value.
Its text MUST give the reason and the release that deprecated it.
When one element replaces it, the release MUST also give `deprecated_element_has_exact_replacement`.
The element MUST stay in the model until the next major version.
Stored data that uses it then still passes validation, and tools can warn before someone uses it in new data.

== Identity and files

[[DMO-063]]
*DMO-063.* The `id` of a schema MUST NOT change from one release to the next.
The files of each release, the source and the generated files, MUST stay available under the tag of that release.
Data and other schemas refer to a model by its `id`.
An old release stays needed for as long as data written under it exists.

[[DMO-064]]
*DMO-064.* A system SHOULD validate data that it receives with the latest minor release of its major version.
That release accepts every record of the earlier minor releases, under DMO-061.
A system that validates with an older release would reject the optional slots that a later release added.
