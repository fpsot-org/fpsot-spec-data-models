= LinkML source and generated files
include::_fpsot-terms.adoc[]

Each {abbr-fpsot-first} model has one source, written in link:https://linkml.io/linkml/generators/index.html[LinkML].
Tools generate every other form of the model from that source.
These rules set the source, the generated files and the checks that keep them in step.

== The source

[[DMO-010]]
*DMO-010.* Each data model MUST have one link:https://linkml.io/linkml/generators/index.html[LinkML] schema as its source, kept under version control in the `model/` folder.
A model SHOULD hold one subject area per schema file, such as `model/party.yaml`.
One source means one place to change the model.
Every other form then agrees with it by construction.

[[DMO-011]]
*DMO-011.* A schema MUST declare its `id`, `name`, `title`, `description`, `version` and `license`.
The `id` MUST be an `https` {abbr-uri-first} under a domain that the publisher controls, such as `https://fpsot.org/model/party`.
The schema MUST declare a `default_prefix` that expands to the `id` followed by `/`.
The `version` follows DMO-060.
These fields tell a reader and a tool what the schema is, who owns it and which release it is.

[[DMO-012]]
*DMO-012.* A schema MUST import the model of the {abbr-fpsot} data types specification, and use its types and classes.
It MUST NOT define its own type for a form that the data types specification sets, such as an interval.
When a tool cannot fetch the import, the repository MAY keep a copy of that model, with no change.
A comment MUST then name the release of the copy.
The Party model imports such a copy, from release v0.1.1 of the data types specification.
Every {abbr-fpsot} model then writes the same {abbr-json-first} form for the same kind of value.

[[DMO-013]]
*DMO-013.* Each class, slot, type and enumeration MUST have a `description`.
The description SHOULD cite the IDs of the requirements that the element follows.
Generated files and documentation copy these descriptions.
A reader then finds the reason for each element in every form of the model.

== Generated files

[[DMO-014]]
*DMO-014.* A tool MUST generate each other form of the model from the link:https://linkml.io/linkml/generators/index.html[LinkML] source.
The repository MUST keep these files under `model/generated/`, and nobody edits them by hand.
For the Party model, the files are:

* a link:https://json-schema.org/draft/2019-09[JSON Schema], to check {abbr-json} data, with the container class `PartyContainer` as its root;
* {abbr-sql-first} table definitions, the raw output of the generator, as one example of a persistence mapping under DMO-070;
* an link:https://www.w3.org/TR/owl2-overview/[OWL 2] ontology in link:https://www.w3.org/TR/turtle/[Turtle], to describe the meaning of the data;
* link:https://www.w3.org/TR/shacl/[SHACL] shapes in Turtle, to check {abbr-rdf-first} data.

A file that people edit drifts from its source, and then two forms of the model disagree.

[[DMO-015]]
*DMO-015.* A check MUST generate each file again, and fail when the result differs from the file in the repository.
The {abbr-ci-first} MUST run this check on every change.
A change to the source then cannot merge until the generated files match it.
A hand edit to a generated file fails the check in the same way.
The script `model/test-model.sh` of this repository runs this check.

[[DMO-016]]
*DMO-016.* The repository MUST fix the release of the LinkML tools that generates its files.
The check MUST fail when it runs with another release.
Two releases of a generator can write different files from the same source.
A fixed release lets the check find drift instead of tool changes.
The Party model uses link:https://github.com/linkml/linkml/releases/tag/v1.12.1[LinkML 1.12.1], and `model/requirements.txt` pins it with the other tools of the check.

[[DMO-017]]
*DMO-017.* Each model MUST have examples of valid data and of invalid data, under `model/examples/`.
The check MUST pass every valid example and reject every invalid one.
Each invalid example SHOULD break one rule, and a comment SHOULD name it.
Examples show how the model reads, and they prove that its constraints work.
The Party model checks each example with LinkML, the generated JSON Schema and the generated SHACL shapes.

== Generators (informative)

The link:https://linkml.io/linkml/generators/index.html[LinkML] tools include a generator for each file of DMO-014: `gen-json-schema`, `gen-sqltables`, `gen-owl` and `gen-shacl`.
The pages on the link:https://linkml.io/linkml/generators/json-schema.html[JSON Schema], link:https://linkml.io/linkml/generators/sqltable.html[SQL], link:https://linkml.io/linkml/generators/owl.html[OWL] and link:https://linkml.io/linkml/generators/shacl.html[SHACL] generators describe their options.
The page of the SHACL generator marks it as a beta.
LinkML 1.12.1 writes the JSON Schema in the 2019-09 dialect.

The script `model/test-model.sh` adds three recorded steps around the generators.
It gives them a copy of the model whose data types import keeps only the elements that Party uses.
It passes `PartyContainer` as the root class of the JSON Schema.
It removes `sh:closed true` from the SHACL shape of `Extensions`, so that the shape accepts any member, under DMO-056.
